# P2-tauri-client report

Silo repo, branch `engine/tauri-client` (worktree `~/silo-work/tauri-client`), cut from `7ecf4035`, merged with `main` (`819c3757`) before the final gate. Never pushed.

## Result

Silo.app (the `silo-ui` crate and its React UI) is now a client of `silod`. It builds no engine, installs no engine context, and runs no engine timers, listeners or stop-on-exit. At launch it uses the engine that already serves `~/.silo/engine.sock`, whichever app supplied it, or registers its own bundled `silod` LaunchAgent. Every Tauri command that called `silo-engine` in-process now forwards to the canonical `silod` method over the socket, using `silo-api` names. The React UI is unchanged apart from the Quit dialogs and the removed legacy theme import.

## Deviations from the spec

1. **Rust adapters instead of `engine_request` + TypeScript client.** p2 section 5.1 calls for one generic `engine_request` command, a native `Channel` event feed, `engine-client.ts` and generated types, with the UI calling canonical methods directly. The task asked for minimal UI change, so each existing command keeps its name and result shape and forwards in Rust (translating names to ids, jobs to final states, wrappers to the legacy shapes). The relay reproduces the established `silo://` events, and also emits every frame as `silo://engine-event`. There is no `engine_request`, no `engine-client.ts` and no generated schema types. The UI therefore still carries its legacy-named call sites; moving them to canonical names is a later UI task, and the adapters are the single place to delete then.
2. **Silo still links `silo-engine`** for five stateless host helpers (`applications`, `notifications`, `system_integrations`, `system_shutdown`, `terminal`): application discovery and launch, notification routing, the login item, Quit reasons, shell quoting. `engine_boundary_tests.rs` forbids everything else (engine construction, `context::current()`, runtime/settings/jobs/transfer calls, the engine runtime crates in `Cargo.toml`). Extracting those helpers into their own crate would remove the link; it was not done to avoid moving files that other tracks edit. The two probe examples (`desktop-viewer-probe`, `recovery-probe`) compile engine modules in place and now use dev-dependencies (`base64`, `libc`, `objc2-virtualization`) so the app no longer depends on them.
3. **`install_update` is the unavailable state.** The engine owns updates (`updates.*`, `updates.changed`); the shared installer that replaces the app and hands the engine over is not built. `get_update_state`, `check_for_update`, `download_update`, `set_update_automatic_checks`, `open_update_release` and the focus nudge forward; `install_update` answers that the update must be installed from the release page. The in-app `tauri-plugin-updater` is still registered but unused.
4. **No engine replacement.** If an engine from another app is already running, Silo uses it, even if older (it logs the comparison); protocol negotiation decides compatibility. Replacing an older engine needs the P3-lifecycle installer.
5. **Dropped legacy features.** `import_legacy_theme` and its UI import are gone (95 section 3). The onboarding draft is client-local (`onboarding-draft.json`), not seeded from the old settings file. The in-process Connections machinery, the `--remote-bridge`, `--remote-guest` and editor-transport launch modes, the startup coordinator, the in-app ChatGPT download worker, the bench harness and the engine-side VM display window host are removed from the Tauri process; `silod` serves them.
6. **Viewer and clipboard.** Linux desktop viewers follow the engine contract (A-5, A-28, A-32): the guest webview gets only the engine's init script, cookie and URL, and `deliver_page` relays only `window.__silo.invoke(...)` scripts to the guest whose `connectionId` matches. Clipboard transfer, sound probe and audio ordering run in the engine (`clipboard.transfer`, `display.viewer.*`); the device clipboard is therefore the engine's pasteboard access, which is a live qualification item for a LaunchAgent.

## Known gaps and what the next tracks need

- **Typed unavailable today.** `retry_runtime_migration` and `continue_after_migration_failure` (no migration retry/continue method exists), `install_update`, and every request for another device (`silod` answers `unsupported_remote_operation` until P3-connections routes by `deviceId`, which covers `remote_*`, `device_snapshot`, remote desktops and remote macOS screens). `macos.display.resize` has no `deviceId` in its params, so a remote resize reaches the local namespace: add `deviceId` or route it in the engine.
- **Capability gate.** Every request is checked against the negotiated capability list before it is sent; a method the engine does not advertise returns the unavailable error without a round trip. This works only because `silod` now advertises what its routers serve.
- **Needs a live pass (owner or Signed Dev):** registering the LaunchAgent from `Silo.app` (and "requires approval"), two apps sharing one engine, Quit with Keep running and Stop and quit against a real engine (engine exit after `engine.shutdown` is treated as completion after a 3 s grace), reconnect after an engine restart, desktop viewers (cookie, init script, page-script relay), VM window in `silod`, upload through a viewer drop (`origin: "viewer"` with the viewer's `connectionId`), embedded signature and Login Items listing of the engine.
- **Release packaging.** `package-macos-release.py` (the release workflow path) does not embed the engine; only `build_desktop.py` does. The release workflow must build `silod` and call `embed_engine.py` before signing. Silo Dev has no bundled agent, so a development run needs an engine started separately.
- **Fjord pin.** Fjord embeds the same engine distribution; the shared per-user installer (B-22/C-9) is still the open item for "newest engine wins".
- **Sidecars for builds.** Building `silo-ui` still needs the ignored `src-tauri/binaries` and `src-tauri/runtime` directories and GitHub build configuration (`github-build.local.json` or the `SILO_GITHUB_*` variables); none was committed.
