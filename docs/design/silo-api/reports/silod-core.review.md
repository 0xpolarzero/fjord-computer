1. **P1: Migration restart can destroy computers just resumed after an update.** [startup.rs:70](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/silod/src/startup.rs:70) starts conversion independently of update recovery. If a pending conversion and saved macOS update journal coexist, recovery can resume the Macs and [discard their captures and journal](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/engine/src/engine_update/transaction.rs:246), then [startup.rs:126](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/silod/src/startup.rs:126) exits directly. The resumed sessions die with silod, with nothing remaining to restore. **Fix:** finish migration and its restart before resuming computers, or save resumed computers again before restarting. **Missing test:** deterministic recovery-before-conversion-completion interleaving.

2. **P1: Voluntary Dock Quit uses forced session-end semantics.** [app.rs:199](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/silod/src/app.rs:199) routes every AppKit termination to `session_end`. That path ignores stop and settings-flush failures; during update preparation, a refusal instead causes [immediate exit](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/silod/src/methods/services.rs:338), potentially killing unsaved macOS computers. **Fix:** distinguish voluntary Quit from logout/shutdown using the [existing Apple-event classification](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/src/commands/system_shutdown/macos.rs:86). Voluntary Quit must preserve cancellation on failure and refuse exit during preparation. **Missing tests:** stop failure, flush failure, and Quit during preparation. A-2 specifically governs Fjord; this finding concerns engine quit data safety.

3. **P1: AppKit’s deferred termination never receives its completion reply.** [app_delegate.rs:68](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/silod/src/app_delegate.rs:68) returns `NSTerminateLater`, but completion only calls [stop plus a posted event](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/silod/src/app.rs:101). Apple requires a subsequent termination reply; [`stop:` inside a modal loop exits that loop rather than the main loop](https://developer.apple.com/documentation/appkit/nsapplication/stop%28_%3A%29?language=objc). The missing reply is confirmed; a lingering process and ownership lease are inferred, not live-reproduced. **Fix:** track and [answer the pending termination request](https://developer.apple.com/documentation/appkit/nsapplication/terminatereply/terminatelater), coordinating cleanup with loop exit. **Missing test:** isolated AppKit subprocess proving termination completes and ownership is released.

4. **P1: Failed or interrupted migrations never retry on later launches.** Both [startup.rs:97](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/silod/src/startup.rs:97) and [runtime_migration.rs:136](/Users/polarzero/code/projects/microsandbox-workspaces/app/SiloUI/src-tauri/engine/src/runtime_migration.rs:136) require `scanning`. Failures persist as `failed`; controller initialization also changes interrupted `scanning`/`running` records to `failed`. With caller-triggered retry retired, fixing a transient disk/export/runtime failure leaves computers permanently blocked. **Fix:** retry verified, writable failed migrations at launch through the existing recovery/conversion path. **Missing test:** failure → reconstructed controller → successful next launch.
