## Fixes

1. **Original resume is armed (P1).** New `ComputerPhase::ResumingOriginal`, journaled before every `resume_held`: abort, rollback, failed preparation, watchdog abort. Recovery of that phase probes the exact original run (`probe_original`: running, held, gone). A held run is resumed again; a running one is settled; a gone one is reported lost with its disk kept. It is never restored from the capture. A failed resume keeps the armed phase, so the guest is never replayed.
2. **Unresolved computers stay reserved (P1).** `engine_update/reservation.rs` keeps the computers a journal still names (or everything, if the journal is unreadable). It is synced after every hold command, abort, recovery and failed preparation. The device operation gate (`OPERATIONS` only) refuses computer-scope admission, deletions (`removing`) and `try_` variants on them, which covers start, delete and configuration changes. `prepare_failed(context)` now sets the pending flag and recovery error when the rollback left a journal, and abort or recovery clears them.
3. **Linux recovery validates first (P1).** A stopped or crashed sandbox is removed only after capture scope, snapshot availability, configuration and the checkpoint record all validated (`restore_plan`). Tests assert that no `remove` runs for a missing capture, unreadable configuration or unverified capture. Residual: the runtime has no rename, so the original sandbox is still removed immediately before `msb restore`. At that point its disk equals the capture, because any advanced run is a lost entry and never reaches restore.
4. **macOS failed restore reports real release (P1).** `ensure_released` is split into a testable `release_machine` loop. A failed restore passes the real outcome to `settle_failed_start`, via `settle_failed_restore`, so the computer stays `Stopping` until the framework proves release. Tests cover refused stops, delayed releases and settling.
5. **Durable capture directories (P1).** `create_durable_directory` runs over a `DirOps` seam: for each level below the computer folder it creates the directory if missing, syncs it, then syncs its parent. Levels that already exist are synced again, so a retry completes a failed sync. Tests cover the exact operation order and a failure injected at each of the six steps.
6. **Abort after release (P2).** `Released` entries in abort mode now go to `abort_held`, which probes the original run. It resumes in place when this process still owns it (macOS paused VM, detached Linux runtime), and restores only when the run is gone. The fake macOS release now keeps the VM paused and owned, as in production. Tests cover release followed by a journal write failure, and a new process.
7. **Run identity (P2).** The journal records `original` and `active_restore` as `RuntimeIdentity {owner, generation, instance}`. Owner is a per-process boot id, since macOS generations restart in every process. Instance is the Linux runtime instance id. The attempt id is journaled with the armed restore. `resume_held`, `release`, `reconcile_unsaved`, `probe_original` and `probe_armed` require exact matches. A replacement run makes `restore` return `RestoreError::Superseded`, so the entry becomes lost, and its capture is neither replayed nor discarded. A Linux restore from capture cannot name its new run before it exists, so its probe requires a different instance than the original and a consumed pending-restore record.
8. **Watchdog and installer ownership (P2).** `engine_update/installer.rs` defines `installer.lock` in the engine directory (an exclusive flock held by the coordinator for the whole handoff), a non-keeping probe, and a `Watchdog` state machine. silod's watchdog thread probes every 5 s. After 30 s of continuous absence, a prepared update is aborted through the same claim a shutdown takes (`aborting` flag vs `shutdown` under one lock). An engine started over a prepared, releasing or released journal, with the lock held and its own version equal to the journal's `sourceEngineVersion` (an old engine relaunched), resumes nothing: it keeps admission closed (`PrepareState::Deferred`), still serves status, abort and shutdown for the update, and restores only when the coordinator has been gone for 30 s. A new version, or no installer, restores at once. A `capturing` journal is always reconciled. `release_for_update` is idempotent once released. The lock file location and protocol are this implementation's choice (see below).
9. **Session-end deadline (P2).** `begin_shutdown` stores one absolute deadline: the earliest of every session-end request (a later SIGTERM tightens it, never loosens it). `run_shutdown` runs the whole work (gate waits, stops, release) on a worker and stops waiting at the current deadline, re-read every 50 ms. A session end then flushes, closes connections and exits. Tests cover earliest-wins, a blocked stop cut off at the deadline, and a second request tightening a deadline already being waited on.
10. **Legacy onboarding draft (P2).** The canonical snapshot is built from `settings::public_snapshot` (the projection every public settings event uses), so update and flush no longer fail. Per 95 §3 the draft is dropped by a launch migration (`settings::discard_onboarding_draft`, called once from `services::start`), not handled per request. Tests cover update, read, flush and events with a stored draft, and the migration.

## Decisions and notes for the next tracks

- Installer contract: the Fjord/installer coordinator must hold an exclusive `flock` on `<engine dir>/installer.lock` (create it) from before `engine.update.prepare` until the new package is verified, and drop it afterwards. `installer::Held` is a ready-made implementation. There is no `install.json` yet, so "the new package" is recognised by engine version differing from the journal's `sourceEngineVersion`.
- Reservations surface as `GateError::Busy` ("Another computer operation is still running."). Adding a dedicated gate error variant would touch many exhaustive matches; consider it when the API error mapping is next revisited. Force stop on a reserved computer is refused too, until abort or recovery settles it.
- The SaveAdapter trait changed (`identity`, `probe_original`, new arguments, `RestoreError`). Both real adapters and the silod fakes were updated; any other implementor must follow.
- A restored Linux run that was never named before it executed (restore from capture) is proved only indirectly (new instance plus consumed pending restore). A real-VM qualification (p2 §3.5) is still the release gate; none of this was run against a live runtime or VM.
- Existing limits unchanged: Linux hold and macOS hold/release remain unqualified until the real-VM transaction tests pass.
