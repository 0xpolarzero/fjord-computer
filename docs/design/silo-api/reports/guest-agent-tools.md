# Guest agent tools (Node.js LTS + Claude Code CLI), 2026-10-14

Silo `engine/guest-agent-tools`, commit `819367b3` (base `c7fc165e`), fast-forwarded into Silo main. Not pushed. No VMs were started: nothing here ran in a real guest.

## What was built
- **Pins** (verified once from the official sources, none downloaded in tests):
  - Node.js v24.21.0 (Krypton LTS): SHA-256 from nodejs.org `SHASUMS256.txt` for linux-arm64/x64 `.tar.xz` and darwin-arm64 `.tar.gz`; sizes via `curl -I`.
  - Claude Code 2.1.287 (the `stable` channel; `latest` is 2.1.299), through Anthropic's documented installer `https://downloads.claude.ai/claude-code-releases/bootstrap.sh` (what `claude.ai/install.sh` redirects to), pinned by SHA-256 `3a68d340...a944`. The installer takes a version argument and checks the binary against Anthropic's release manifest. Auto-update is off (`DISABLE_AUTOUPDATER=1`). No login.
- **Linux**: `guest/agent-tools.py` + `guest/agent-tools-lock.json` (recipe version 1). Runs as root: downloads over HTTPS, verifies SHA-256, extracts Node to `/opt/silo/node/<version>` (unsafe archive members refused), links `node npm npx` into `/usr/local/bin`; runs the installer as the `silo` working account, links `/usr/local/bin/claude`; writes `/var/lib/silo/agent-tools.json` last. Idempotent. Independent of the guest image (no image republish needed); it is a separate action, not part of `setup-desktop.sh`.
- **Engine**: `engine/src/agent_tools.rs`. New desktop action `setup-agent-tools` (`DesktopAction::SetupAgentTools`; 30 min timeout, allowed on computers without a desktop, forwarded to remote devices). Existing computers get the update path from the recipe number: status reports `outdated` when the receipt's recipe is older than the bundled one; bump `recipeVersion` in the lock (or the pinned versions) to roll an update.
- **Status**: `DesktopStatus.agentTools` (in `desktop.status`, `desktop.action` result) with `state` ready | missing | outdated, `missing` (`node`/`claude`), `nodeVersion`, `claudeVersion`, `expected*` versions, `recipeVersion`, `expectedRecipeVersion`. Null for a stopped Linux computer (it cannot be inspected). Linux status reads live `node --version` and `claude --version` (as `silo`). macOS status is derived from the record: not installed -> missing; developer-tools fingerprint stale -> outdated; current -> ready with the pinned versions. JSON schema regenerated (`api/schema/silo-api.schema.json`); Fjord's Swift client needs regenerating to see the new field and action.
- **macOS**: the developer-tools step (`silo-developer-tools.zsh`, `developer-tools-lock.json`) now also installs Node (host downloads and verifies the tarball like gh/git-lfs, then it is staged in the guest, extracted to `/usr/local/libexec/silo-tools/<v>/node`, linked into `/usr/local/bin`) and Claude Code (host stages the pinned `bootstrap.sh`; the guest runs it as the working account; `/usr/local/bin/claude` links to `~/.local/bin/claude`). Receipt gains `nodeVersion`/`claudeVersion`. The setup fingerprint (`developer_tools::version()` hashes script + lock) and the tools-version string changed, so existing macOS computers and the template become stale and take the existing retry/refresh path.
