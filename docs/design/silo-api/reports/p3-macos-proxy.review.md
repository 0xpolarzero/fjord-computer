Seven follow-up findings, ranked by impact. Line numbers refer to `aec93970`; unrelated merge changes were excluded.

1. **P2: Packet bursts can strand queued frames indefinitely.** [frames.rs:268](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/macos-gateway/src/frames.rs:268) limits backend reads to 32 frames. The pinned backend drains its entire wake pipe before popping a frame. Remaining ring entries therefore lose their notification; after pending sends finish, `poll(-1)` can sleep until another producer write. **Follow-up:** preserve readiness while the ring contains frames, preferably through an upstream backend fix. Regress a 33-frame burst with no subsequent producer activity.

2. **P2: Failed bootstrap leaves setup falsely complete and Retry unavailable.** [provision.rs:235](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/engine/src/macos_computers/provision.rs:235) stages network and trust after all setup flags are persisted. A copy, CA-install, or identity-write failure leaves `setup_complete()` true. Retry then rejects the computer as already configured, while Start rejects its missing bootstrap and requests Retry. **Follow-up:** include bootstrap completion in readiness and Retry admission, and explicitly use temporary NAT when retrying unfinished bootstrap. Inject a staging failure after the last setup flag and verify recovery without relaunching.

3. **P2: Migration rejects already migrated computers with saved memory and suppresses unrelated recovery.** [macos_computers.rs:2013](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/engine/src/macos_computers.rs:2013) rejects `pending_restore.memory` before checking whether bootstrap already matches. The resulting error makes [startup.rs:243](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/engine/src/startup.rs:243) skip lifecycle recovery, update recovery, and automatic starts for the entire application. **Follow-up:** check existing bootstrap first; restrict the cold-boot prohibition to guests requiring conversion, and allow unrelated recovery to continue. Cover migrated and legacy memory restores alongside an unaffected second computer.

4. **P2: Larger EDNS DNS answers disappear instead of triggering TCP fallback.** [frames.rs:266](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/macos-gateway/src/frames.rs:266) accepts only a 1500-byte IP packet. The pinned DNS forwarder truncates against the advertised EDNS limit, then constructs one unfragmented UDP frame. With EDNS 4096, a DNS payload exceeding 1472 bytes is discarded by the backend; the guest receives neither an answer nor `TC=1`. **Follow-up:** cap UDP DNS responses against both EDNS and guest MTU upstream. Test a roughly 2 KiB answer followed by successful TCP fallback.

5. **P2: DNS ignores split resolvers and changes after gateway startup.** [supervisor.rs:399](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/engine/src/macos_computers/proxy/supervisor.rs:399) always requests host DNS discovery. The pinned implementation reads only `State:/Network/Global/DNS`, once during construction. Supplemental VPN domains use the global resolver, and a running gateway retains old servers after a network change. **Follow-up:** add host resolver routing and Dynamic Store refresh upstream, preserving DNS identity binding. Cover supplemental domains and resolver changes while the gateway remains running.

6. **P2: CA readiness accepts a present but untrusted certificate.** [silo-network-bootstrap.swift:500](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/guest/macos/silo-network-bootstrap.swift:500) checks certificate presence by fingerprint. Its HTTPS probe uses `example.com`, which bypasses interception unless a secret allows that host. Removing trust settings while retaining the certificate can therefore produce a ready receipt, although native clients fail against intercepted destinations. **Follow-up:** evaluate a leaf signed by the current CA using normal guest trust, or use a guaranteed intercepted probe. Regress a present-but-untrusted CA.

7. **P3: Computer deletion retains CA private keys and lock entries.** [proxy_ca.rs:24](/Users/polarzero/silo-work/p3-macos-proxy/app/SiloUI/src-tauri/engine/src/macos_computers/proxy_ca.rs:24) provides no deletion operation; computer deletion removes filesystem state only. Its strong per-computer lock map also never shrinks. **Follow-up:** retire channel-scoped CA items once computer and saved-generation references are gone, make failed cleanup retryable, and prune unused locks. Cover repeated creation and deletion.
