1. **P1: Failed subscription restoration permanently poisons reconnect.** [SocketEngineClient.swift:486](/Users/polarzero/code/projects/lookout/Sources/Fjord/SocketEngineClient.swift:486) stores `candidate` before restoring subscriptions. If `events.subscribe` returns an RPC error, the catch closes that candidate but leaves it cached. The next reconnect attempt returns the closed transport and exits successfully; subsequent requests fail indefinitely. **Fix:** publish the transport only after restoration succeeds, and clear the matching candidate on failure.

2. **P2: Socket backpressure blocks response handling and shutdown.** [SocketEngineClient.swift:203](/Users/polarzero/code/projects/lookout/Sources/Fjord/SocketEngineClient.swift:203) runs blocking `send` inside the transport actor. A peer that stops reading can stall a request below the 4 MiB limit, preventing `receive`, `close`, and disconnect requests from entering the actor. **Fix:** use nonblocking I/O or a dedicated I/O executor, preserve serialized frame writes, and allow shutdown independently of the blocked writer.

3. **P2: Reconnect delivers events before resync.** [SocketEngineClient.swift:500](/Users/polarzero/code/projects/lookout/Sources/Fjord/SocketEngineClient.swift:500) restores subscriptions sequentially. After restoring A, it awaits B while A’s events can already reach its handler. `.reconnected` arrives only after all restorations finish, violating §4.2’s requirement to reread before using subsequent events. **Fix:** buffer events throughout restoration and signal resync before draining them.

4. **P2: Request cancellation leaves callers suspended.** [SocketEngineClient.swift:200](/Users/polarzero/code/projects/lookout/Sources/Fjord/SocketEngineClient.swift:200) registers a continuation without cancellation handling. Canceling a caller while the server withholds its reply neither releases the waiter nor removes the pending entry. Already canceled tasks can also send requests. **Fix:** check cancellation before sending, resume canceled waiters with `CancellationError`, and recognize late replies without disconnecting unrelated requests. Local cancellation must remain distinct from `operations.cancel`.

5. **P2: Disconnect during handshake allows requests afterward.** [SocketEngineClient.swift:425](/Users/polarzero/code/projects/lookout/Sources/Fjord/SocketEngineClient.swift:425) returns when `transport` is nil, leaving an opening connection untouched. A delayed handshake subsequently publishes its candidate, and the original invocation sends its domain request after disconnect. **Fix:** retain and close the opening candidate, invalidate its generation, and check disconnect state after suspension points.

6. **P2: Unsubscribe during restoration resurrects the subscription.** [SocketEngineClient.swift:498](/Users/polarzero/code/projects/lookout/Sources/Fjord/SocketEngineClient.swift:498) copies a subscription before awaiting its restoration response. Unsubscribe can remove it during that await; restoration then reinserts the stale handler and new server ID. **Fix:** revalidate subscription membership and connection generation after the await. Unsubscribe the returned server ID if the local subscription was removed.

7. **P2: Intentionally ignored events create false sequence gaps.** [SocketEngineClient.swift:578](/Users/polarzero/code/projects/lookout/Sources/Fjord/SocketEngineClient.swift:578) advances its sequence before dropping unprojected events. `computers.unexpectedChange` matches the model’s `computers.*` subscription but is dropped.
