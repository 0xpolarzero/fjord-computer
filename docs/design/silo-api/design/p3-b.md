Ship macOS computers through the existing engine API, using a supervised frame gateway for credentials and the existing SSH transport for guest services.

This design consumes the Phase 1 `silo-engine` / `EngineContext` extraction and `silo-api` types, and the [Phase 2 design](p2.md). It creates no second engine, job registry, event protocol or credential store. Implementation paths below are relative to the eventual Rust workspace; locate extracted modules after P1 merges. Proposed structures and paths are design choices, not claims that they exist. Only this design document was written; no code, VM, settings, or protected probe record was changed.

## 1. P3-macos-proxy

### 1.1 Decision: a gateway child per VM

Keep `VZVirtualMachine`, its FileHandle attachment and window inside `silod`. Run the datagram adapter and patched `SmoltcpNetwork` in **one signed `silo-macos-gateway` child per running VM**, supervised by `silo-engine`. A child has no LaunchAgent registration, UI, public admin listener, Connections dispatcher or independent policy authority. It receives only that computer's effective policy and credentials through inherited private descriptors. This is the production boundary selected from the working two-process probe, not a claim that its admin protocol is suitable for production. [95 A-15](../95-decisions.md#1-owner-decisions), [50:848](../50-access-network-files.md), [prototype host.swift:100](/Users/polarzero/silo-probes/proxy/src/host.swift:100), [gateway.rs:65](/Users/polarzero/silo-probes/proxy/src/gateway.rs:65).

The in-process alternative saves two IPC endpoints and process overhead, but exposes the VM owner to failures in packet parsing, TLS tasks and the krun backend. Per-VM children contain that failure and preserve a direct per-computer secret boundary. They still trust the host user: process separation is not a sandbox against another same-euid application. The cost is helper packaging, descriptor handoff, restart/reconciliation and measured RSS/CPU. Limit the host to the framework's two running macOS guests; Linux guests do not consume those slots. `src-tauri/src/macos_computers/engine.rs:43`, `:125`; [30:78](../30-macos-computers.md).

Reuse **MicroSandbox 0.7.6 at `09df3d4b9d832adaede1fb9a198cfc660bfab8cd` with Silo's network patch**. Its public network builder, backend and secret handle already supply the required policy. Do not port the probe's Python DNS/echo servers or replace its TLS core. [92 §§1–4](../92-macos-proxy-research.md), [proxy:12](../probes/proxy.md), `src-tauri/../runtime-inputs.json:62`, `src-tauri/../patches/microsandbox-silo-network-0.7.6.patch:1368`, `:1941`.

Prior-art decision: Apple's NAT attachment remains the installer/recovery bootstrap; it supplies no credential substitution. An explicit mitmproxy CONNECT deployment supplies TLS interception but requires cooperative clients and new GitHub selection/revocation integration. Patched MicroSandbox preserves both host-enforced routing and the existing Silo credential behavior. Apache-2.0 permits reuse; preserve notices and audit the complete dependency licenses at packaging. The pinned release and patch hashes, not a moving branch, define the supported production build. Prefer upstream additions for missing reusable PEM-bytes, endpoint reservation and policy-ack seams; keep macOS bootstrap/product policy in Silo. [92:23](../92-macos-proxy-research.md), [92:35](../92-macos-proxy-research.md), [92:41](../92-macos-proxy-research.md), [Apple attachment](https://developer.apple.com/documentation/virtualization/vzfilehandlenetworkdeviceattachment), [mitmproxy modes](https://docs.mitmproxy.org/stable/concepts/modes/).

### 1.3 Internal structures and transport

```text
ProxyIdentity {computer_id, network_slot, guest_mac, guest_ipv4, prefix_len,
               gateway_ipv4, gateway_mac, mtu, ca_id, bootstrap_version}
GatewayLease {computer_id, vm_generation, child, vm_datagram_fd,
              control_fd, helper_generation, applied_policy_revision,
              ssh_endpoint, screen_endpoint, status}
GatewayInit {protocol_version, identity, effective_network_policy,
             secret_material, github_profile, ca_cert_pem, ca_key_pem}
PolicyUpdate {vm_generation, helper_generation, revision, changes}
PolicyApplied {revision, effective_names_and_hosts, cancelled_connections}
ProxyReceipt {schema_version, computer_id, bootstrap_version, ca_fingerprint,
              placeholders_generation, verified_at}
```

`ProxyIdentity` and receipts contain no values. Persistent secret material remains in the existing channel Keychain. Store per-computer CA private keys there too, under a new channel-derived service/account namespace; only public certificates and fingerprints belong in `macos-computers/<id>/`. Never serialize `GatewayInit` into jobs, diagnostics, computer records or archives. Do not derive Debug for material or grants at the adapter boundary. Internal control messages use bounded length-prefixed frames on an inherited `AF_UNIX/SOCK_STREAM` pair; raw Ethernet uses a separate connected `AF_UNIX/SOCK_DGRAM` pair. The helper accepts no filesystem socket path or TCP admin port from a guest. Every mutation/ack includes owner generations and monotonic policy revision. This adapts P2 framing machinery without making this a second public protocol. `src-tauri/src/secrets.rs:60`, `src-tauri/src/github.rs:1698`; [05:741](../05-engine-architecture.md), [prototype gateway.rs:126](/Users/polarzero/silo-probes/proxy/src/gateway.rs:126).

Use close-on-exec on every descriptor except the precise child handoff set. Retain the VM end for the attachment's lifetime; the engine retains the gateway end so it can attach a replacement child after confirmed old-child exit. Only one child may read that endpoint. Control EOF ends the child; a stream control FD supplies reliable parent-death detection, which a datagram pair alone does not guarantee. Explicit stop: drain/cancel transfers, stop VM while SSH still works, close its relays, stop/wait child, release descriptors. Helper failure: close all host listeners, mark proxy unavailable, replace child with **current** policy before resuming traffic. Never switch a running computer to NAT after a gateway failure. Repeated failures preserve the VM and report network failure; no automatic cold restart. [P2 §1.7](p2.md), `src-tauri/src/macos_computers.rs:1783`, [proxy:129](../probes/proxy.md).

**Correct the prototype summary's header direction in implementation.** FileHandle receives/sends Ethernet datagrams. The probe feeds guest datagrams with `backend.write_frame(0, ...)`, without stripping a header; it strips the **backend's outgoing** 12-byte virtio header before sending to VZ. The prose in 50/proxy.md describes that direction imprecisely. Follow actual code: [gateway.rs:237](/Users/polarzero/silo-probes/proxy/src/gateway.rs:237), [gateway.rs:249](/Users/polarzero/silo-probes/proxy/src/gateway.rs:249); MicroSandbox `crates/network/lib/engine/netstack/backend.rs:65`, `:91` at the pin.

Set MTU explicitly from the network's bootstrap configuration. Use `recvmsg` truncation detection, minimum Ethernet/IP lengths, bounded queues, explicit drop counters, interrupted-I/O retry, fair batches in both directions and a control wakeup. Retain an outgoing datagram on `EAGAIN` until writable; the prototype consumes it then breaks, losing it (`gateway.rs:253`). Handle backend ring-full as a measured drop/backpressure condition instead of killing the child. Reject guest source MAC/IP spoofing, malformed ARP, and unsupported frame types before routing. V1 supports IPv4 and returns useful negative AAAA results; disable guest IPv6 and reject IPv6 frames until the full policy path is qualified. Do not allow UDP/QUIC to evade the Linux TLS policy. Preserve the existing network policy rather than copying the probe's broad `Host` profile into production. [gateway.rs:73](/Users/polarzero/silo-probes/proxy/src/gateway.rs:73), [gateway.rs:261](/Users/polarzero/silo-probes/proxy/src/gateway.rs:261), MicroSandbox `engine/network.rs:475`, `engine/netstack/backend.rs:192`; [92 §1](../92-macos-proxy-research.md#1-linux-path-today).

### 1.4 Addressing, route bootstrap and DNS fix

Allocate a stable, persisted `/30` identity per computer, initially from `172.30.0.0/16`: guest `base+2`, gateway/DNS `base+1`. The addresses are guest-internal, not host routes or LAN leases. Check overlap with host/VPN destinations at allocation and report conflicts; never rewrite an identity with saved memory. More computers can exist than run; network slots are unique across stored identities and reused only after deletion and all saved-generation references are gone. Guest MAC remains the record's fixed locally administered MAC. Ask `SmoltcpNetwork` for its bootstrap tuple and derived gateway MAC, then persist/validate it rather than duplicate its arithmetic. [proxy:52](../probes/proxy.md), [30:299](../30-macos-computers.md), `src-tauri/src/macos_computers/engine.rs:309`; MicroSandbox `engine/network.rs:175`, `:244`, `:475`.

The host cannot dial this guest IP as if it were an Apple NAT lease. Publish private **loopback-only** helper endpoints for guest SSH/22 and Screen Sharing/5900 through the network engine's inbound port path. Use assigned/reserved ephemeral ports, never `20000+slot`. If the existing public builder cannot return the bound port or accept a reserved listener, add that small seam upstream and regress it; a bind/free/rebind guess is not ownership. Hide both endpoints from `network.state`; 5900 is never a user-published desktop port. `GuestEndpoint` selects `Nat {address}` only for setup/recovery, or `Gateway {loopback endpoints, generation}` for ready VMs. All SSH/SFTP/clipboard/recording/display callers use it. [95 A-34](../95-decisions.md#2-technical-defaults-claude-veto-any), `src-tauri/src/macos_computers/guest_access.rs:260`, `remote_display.rs:84`; MicroSandbox `engine/ports/publisher.rs:61`.

**The fix is to configure the active network service and resolver, not merely set an interface address.** The prototype hard-codes `Ethernet`/`en0` and mixes persistent `networksetup` preferences with direct `ifconfig`/`route`. Its B evidence also contains a DHCP `en1` service alongside manual `en0`. Successful explicit DNS proves the frame DNS path, not that the OS selected it. No failed-run `/etc/resolv.conf` or `scutil --dns` capture survives, so the exact historical cause is unproved. [prototype run_guest.sh:92](/Users/polarzero/silo-probes/proxy/src/run_guest.sh:92), [proxy:84](../probes/proxy.md), [guest-B-network-config.txt:1](/Users/polarzero/silo-probes/proxy/evidence/guest-B-network-config.txt:1), [guest-A-frame-debug.log:15](/Users/polarzero/silo-probes/proxy/evidence/guest-A-frame-debug.log:15).

Install a root guest LaunchDaemon with a native SystemConfiguration helper and a public, per-computer bootstrap receipt. On every boot it:

1. Finds the NIC by expected MAC, then its `SCNetworkService` by BSD device name. Creates/enables a service in the active network set if missing; selects that service first for the managed one-NIC configuration. No localized service-name or fixed `en0` assumption.
2. Sets IPv4 Manual address/subnet/router and DNS `ServerAddresses=[gateway]` together; disables IPv6 for v1. Calls `SCPreferencesCommitChanges` **and** `SCPreferencesApplyChanges`. Persistent preferences alone are not readiness. Watches active Dynamic Store state and retries boundedly while the device appears.
3. Confirms live interface address, connected/default route through that interface, `State:/Network/Service/<id>/DNS`, global resolver selection and `scutil --dns`. Lets configd generate `/etc/resolv.conf`; verifies it names the gateway for tools such as `dig`. Do not permanently hand-edit that generated file or use cache flushing as a substitute for configuration.
4. Runs explicit `dig @gateway`, then **plain `dig`**, native `getaddrinfo`/`dscacheutil`, and HTTPS without `--resolve` or `--cacert`. Marks ready only after all pass; a timeout retains diagnostics and fails setup. Retry a boot-time race, never swallow route errors with `|| true`.

This is a concrete fix to implement and test, not a retroactive claim that B-27 is settled. Apple's framework separates stored configuration from active configuration; commit/apply are the supported seam. ISC documents that `dig` without `@server` reads `/etc/resolv.conf`. [Apple SystemConfiguration overview](https://developer.apple.com/library/archive/documentation/Networking/Conceptual/SystemConfigFrameworks/SC_Overview/SC_Overview.html), [SCNetworkConfiguration](https://developer.apple.com/documentation/systemconfiguration/scnetworkconfiguration), [SCPreferencesApplyChanges](https://developer.apple.com/documentation/systemconfiguration/scpreferencesapplychanges(_:)), [ISC dig](https://bind9.readthedocs.io/en/stable/manpages.html#dig-dns-lookup-utility).

DNS forwarding stays in patched MicroSandbox, using its host resolver configuration, including VPN/split-DNS behavior. Do not ship the probe's hard-coded `1.1.1.1` or loopback 53535 server. Capture DNS requests at the frame/forwarder boundary without payload credentials. Test UDP/53, TCP/53 fallback, A/AAAA, negative answers, CNAME, oversized/truncated responses, host resolver changes and cache reuse before substitution. Clear/reconcile DNS bindings when replacing a helper; maintain hostname/TLS identity validation and reject ambiguous/stale authority instead of substituting from IP alone. [prototype dns_server.py:8](/Users/polarzero/silo-probes/proxy/src/dns_server.py:8), [92:27](../92-macos-proxy-research.md), `src-tauri/../patches/microsandbox-silo-network-0.7.6.patch:396`.

Fresh installation uses NAT through account creation and Recovery, with no assigned host credentials. At root finalization, stage the network helper/config, certificate and placeholder setup over existing SSH; shut down; rebuild with **one FileHandle NIC**, then verify route/DNS/CA/SSH. New ready computers always use the gateway, even without assigned secrets. Template copies and forks stage their new identity while stopped or under restricted personalization NAT, then repeat the gateway boot check. Conversion of existing records runs only in launch `runtime_migration`; incomplete provisioning blocks ordinary Start and uses Retry setup. Do not keep NAT plus FileHandle as two simultaneous egress routes. [30:478](../30-macos-computers.md), `src-tauri/src/macos_computers/provision.rs:134`, `offline_setup.rs:675`, [95 §3](../95-decisions.md#3-amendments-owner-2026-10-13-later).

### 1.5 CA, secrets and GitHub lifecycle

Generate one stable CA per computer. Deliver **only its public certificate** during the running-guest root-finalization or personalization step, then run:

```sh
/usr/bin/security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain /Library/Application\ Support/Silo/proxy-ca.pem
```

Read back the fingerprint and verify a synthetic intercepted HTTPS request with the guest's normal trust settings. Install before enabling any real-value substitution. Template publication strips per-computer certificates/receipts; personalization removes only Silo-owned inherited trust by recorded fingerprint, installs the child's CA and verifies it before replacing credentials/marking complete. A cloned **System** keychain is not cleaned by today's removal of the user's `~/Library/Keychains`. Never export the host CA private key. Reboot/retry is idempotent; CA rotation stages new trust, verifies it, changes gateway CA, then removes old trust. Maintain old key until saved generations needing it are gone, or invalidate their restore explicitly. `src-tauri/src/macos_computers/personalize.rs:53`, `offline_setup.rs:675`; [proxy:54](../probes/proxy.md), [92:45](../92-macos-proxy-research.md).

The network builder currently takes CA file paths. Prefer a reusable upstream PEM-bytes constructor so `silod` can send the key on the private FD without an on-disk helper secret. If a temporary file is required by the pinned API, use a private 0700 child directory and 0600 key, no-follow opens, remove immediately after load and sweep crash leftovers before admitting traffic. Persistent storage remains Keychain; this exception concerns loading the TLS library, not a replacement credential store. `prototype/gateway.rs:77`, `prototype/prepare.sh:39`; MicroSandbox `engine/network.rs:523`, [92 §2](../92-macos-proxy-research.md#2-is-the-proxy-separable).

### 1.6 Isolation, cost and risks

Each VM has a distinct datagram pair, child, network instance, DNS bindings, subnet/slot, CA, grants, control FD and generation. No shared mutable secret/DNS profile or fixed admin port. The probe's A/B were sequential; the fixed-admin-port confusion was corrected once and does not prove simultaneous isolation. [proxy:114](../probes/proxy.md), raw `nat-benchmark-A.txt`, `frame-benchmark-A.txt`, `guest-B-frame.log` under `~/silo-probes/proxy/evidence/`.
