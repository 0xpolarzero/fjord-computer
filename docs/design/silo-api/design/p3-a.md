### 1.1 One domain implementation and one wire definition

All wire additions go into P1's `silo-api`, including schema/serialization fixtures and generated client artifacts. Engine behavior belongs in P1's `silo-engine`, using its `EngineContext`; `silod` only authenticates, routes and dispatches. Reuse P2's `RequestContext`, SQLite-backed jobs/claims, cancellation, event projections and per-client SSH relay. Do not add Tauri state, a second job store, a new frame codec or another OAuth broker ([05 §2.5](../05-engine-architecture.md#25-enginecontext-the-interface-the-library-needs-instead-new), lines 393–465; [p2 §§1.6, 2](p2.md#2-p2-jobs-events)).

## 2. P3-guest

### 2.1 Scope and contracts

Provide the same guest account, bounded execution, exec jobs, programmatic files and SSH aliases for Linux and macOS computers. All wire addressing uses `computerId`, with optional `deviceId` selecting the owner through the local engine. This track also implements `guest.exec.input/get` and the `guest.prepare/ssh` adapters that the requested features require. It does not install Fjord's product hook/plugin or implement its Router logic; Phase 4 consumes these generic capabilities ([70 §2.1](../70-fjord-needs.md#21-engine-methods-generic-guest), [50 guest.*](../50-access-network-files.md#guestprepare), [10 §0.2](../10-computers-lifecycle.md#02-addressing-a-computer-local-and-remote-with-one-method)).

Reuse P1 `EngineContext`, `silo-api` bytes/errors/schema and P2's request context, job acceptance/completion storage, cancellation and subscriptions. Exec output uses `guest.exec.output/exited`, not a new `operations.job.progress` source. Completed outcomes survive restart until `operations.job.acknowledge`; client disconnect does not cancel execution. No operation gate belongs to guest exec or an already-prepared interactive stream. Guest-key preparation retains its computer gate and revalidation ([05 job contract](../05-engine-architecture.md#job-contract), [95 A-2/A-37 and §3](../95-decisions.md#3-amendments-owner-2026-10-13-later), [P2 §§2.1–2.4](p2.md#2-p2-jobs-events); source `src/remote_access.rs:184`, `:197`).

### 2.3 Wire methods and internal data

Use these fields exactly, with P1 serialization/schema. Shared selectors are flattened on per-computer requests. P2 routes owner-scoped job calls using `(deviceId,jobId)`; 70 does not restate `deviceId` on input/get, so wire generation must reconcile that shared selector before dispatch rather than create remote aliases.

| `guest.files.read` | `{computerId,deviceId?,path,offset?,length?}` → `{data,size,mtimeMs,inode,mode}` |

Sources: [70 guest.account through guest.files.watch](../70-fjord-needs.md#guestaccount), [50 guest.prepare/ssh/aliases](../50-access-network-files.md#guestprepare), [05 job result and remote-owner contract](../05-engine-architecture.md#job-contract). Guest errors include `not_running`, `account_not_migrated`, `timed_out`, `output_too_large`, `cancelled`, `stdin_closed`, `not_found`, `permission_denied`, `not_a_file`, `exists`, `changed`, `open_ssh_missing`, and `include_not_writable` as specified in 50/70; add them to P1's existing errors, not a separate string decoder.

Validate before effects: nonempty argv, no NUL in executable/arguments/paths, absolute cwd/file paths, nonempty environment names without `=` or NUL, and positive bounded-exec timeout. Reject duplicate environment names rather than make precedence accidental. Check offset/length arithmetic and permission-bit ranges before SFTP or helper dispatch. Require a valid digest for `ifSha256` unless expected hash is explicitly null; reject inconsistent replace/hash combinations. These are adapter validation choices, with canonical error fixtures. Removal executes files in request order; a later failure does not undo earlier unlinks. Preserve an actionable error and let explicit retry safely treat absent files as removed, without claiming a multi-file transaction ([70 §2.1](../70-fjord-needs.md#21-engine-methods-generic-guest), lines 185–195, 252–278, 300–311).

Internal account credentials remain distinct from the wire account. Linux `working_account::inspect_user` currently checks managed runtime support and returns only `silo`; macOS `GuestAccount` is `user/password/key`, not uid/home (`src/working_account.rs:118`, `:128`; `src/macos_computers/guest_access.rs:43`, `:77`). Query uid/home inside the running guest; never derive guest uid from host euid or return credentials.

`ExecSession` holds `jobId`, `computerId`, guest generation/boot identity, process handle, stdin state, cancellation token, next output sequence, first retained sequence, replay deque and retained-byte/encoded-byte counts. Choose one increasing output sequence across stdout/stderr chunks, distinct from event-envelope sequence; chunk before publishing and retain a bounded deque across both streams. Bound both bytes and entry count, including one-byte alternating-stream writes: a byte-only budget does not bound JSON/chunk overhead. Initial implementation choices are at most 1,024 retained chunks and 64 KiB encoded output per event, subject to B-32/B-35 measurement. Evict whole oldest chunks whenever the requested byte budget, entry budget or complete encoded-get budget would overflow, and advance `firstRetainedSeq`; retention is an upper bound, not a claim that all output survives. Validate `retainOutputBytes` at admission against P1's actual encoded bytes and the worst-case `guest.exec.get` envelope, including per-chunk overhead, so a complete permitted replay reply fits 4 MiB; reject an invalid requested budget before launching. These are new implementation limits, requiring serialization fixtures and B-32 measurement. Persist final exit/signal in the P2 owner registry before completion. Completed `guest.exec.get` can return empty output after restart with an honest `firstRetainedSeq`; output-ring persistence and running continuation are separately qualified by B-37. `lost` denotes unresolved active-process tracking, not expiry of a completed outcome.

`WatchRegistration` holds subscription ID, authenticated client/session owner, target computer/generation, watched folders, helper handle and coalescing set. Use P2 subscription ownership/disposal and the existing `events.unsubscribe {subscription}` mechanism for the parameterized watch's returned ID, after confirming this ID mapping in the wire fixture; do not add `guest.files.unwatch`. Disconnect disposes watches, not submitted jobs. A stop or generation change ends the registration. Reconnect creates a fresh subscription and re-reads; hints never claim file content is authoritative.

### 2.4 Platform execution, file commits and alias routing

**Linux execution.** Construct `msb exec` with `--no-start --no-tty`, explicit user/workdir/env and argv after `--`; preserve runtime proxy/environment injection and restore-start guards. Current `runtime_arguments` inserts `--no-stdin` for every non-TTY execution because Silo's process stdin carries startup secret data (`src/runtime.rs:1082`, `:1523`). Add an explicit guest-input mode at the process seam; do not globally remove that protection. Account execution sets `USER/LOGNAME`, as the existing directory handoff does (`src/editor.rs:62`). Qualify byte output, stdin and actual guest exit status rather than assuming the host CLI status is equivalent.

**macOS execution.** Use authenticated SSH through `guest_access` and individually quote argv/env/cwd into fixed wrapper source. The existing runner sends a single command string and supports `sudo -n` root work (`src/macos_computers/guest_access.rs:361`, `:454`, `:526`, `:695`). Caller arguments are data, never inserted as shell source. Raw bytes and signal-preserving output are new: current `CommandOutput` uses strings, lossy UTF-8 and signal status `-1` (`:36`, `:661`, `:668`).

**Cancellation and deadlines.** The existing runner kills/waits only the host SSH child on overflow, cancellation or timeout (`src/macos_computers/guest_access.rs:637`, `:642`, `:650`). That does not prove guest process termination: B-12 observed the guest command survive ProxyCommand death. Prototype a guest process-group supervisor/control mechanism with run token and boot/generation identity; send SIGTERM, wait a measured grace period, SIGKILL if needed, and confirm guest exit before declaring cancellation. Never signal a recycled PID. Apply the same cleanup mechanism to bounded timeout/overflow. No Tauri cancellation flag or transport kill counts as proof of guest exit ([05 §4.2 F](../05-engine-architecture.md#f-cancellation), [70 guest.exec.start](../70-fjord-needs.md#guestexecstart), [B-12](../probes/linux.md#b-12--proxycommand-disconnect)).

**Bounded-result memory and framing.** Preserve uncapped stderr draining by spooling stderr to a private engine-owned temporary file rather than retaining unbounded RAM; clean it after reply/failure and at startup after abandoned requests. This storage choice does not impose a new stderr cap. Before reply, serialize/measure the complete stdout/stderr result using P1 encoding and a bounded writer. If it cannot fit the 4 MiB frame, return the existing canonical `internal` protocol-size failure with a precise diagnostic, never successful truncation or a second stderr `output_too_large` rule. Likewise, an unpaged `guest.files.list` whose complete encoded result does not fit returns that existing failure rather than silently paging/truncating. Qualification must cover disk exhaustion, spool cleanup, maximum byte expansion and serialized envelope overhead. These are implementation choices requiring fixtures/B-32; if the owning spec demands success for such oversized values, amend that exact result/error contract before release.

**File transport and commits.** Reuse SFTP on both guests for account-readable byte transport, with guest-side metadata/native commit/watch helpers as necessary. Stage a write in the destination directory at its final mode, create missing parents at 0700 when requested, then commit atomically. `never` and `ifSha256:null` require a true no-replace commit; “test absent then rename” is incorrect. `ifSha256` compares inside the guest immediately before commit, with engine requests serialized per target across local/remote clients. Ordinary hash-check plus rename is not universal CAS against non-engine writers. Primary-source qualification of native Linux/macOS commit primitives, concurrent external edits, symlink behavior and helper runtime availability is a release gate; the design does not assert that stock SFTP solves it. Do not advertise conditional writes until the observable contract is either proved or amended explicitly. Read metadata from the open file so replacement cannot pair old bytes with a new inode; remove unlinks files without traversing symlink targets and refuses directories ([70 guest.files.write/read/remove](../70-fjord-needs.md#guestfileswrite); existing SFTP transport `src/transfer.rs:1316`, existing macOS SSH options `src/macos_computers/guest_access.rs:361`).

**Alias ownership is a routing exception.** Even with `deviceId`, ensure/remove edit the controller Mac's config. Its local engine obtains owner account/path/key preparation, then writes controller-local `*.conf`/Include. A blind relay of ensure to the owner would return unusable paths. This division already exists around remote preparation (`src/editor.rs:755`). Key config/known-host/alias identity by `(channel,deviceId?,computerId)` independently of name and storage location. Use `silo[-dev]-<computerId>` locally and the existing channel-specific `silo[-dev]-remote-<deviceId>-<computerId>` remotely, with UUID-keyed `.conf`/known-host filenames. These spellings use allowed deep-link characters; package paths remain P2/C-9 authority. Keep pinned host key, `IdentitiesOnly yes`, `IdentityAgent none`, disabled agent/X11 forwarding and trailing `Host *` (`src/editor.rs:564`, `:593`, `:781`). Remove retained-name alias code (`:598`) without fallback; any required conversion happens once at launch.

`installInclude:false` skips installation and reports actual presence; a requested installation failure is an error. Preserve owned-symlink Include handling and atomic private writes (`src/editor.rs:423`, `:460`). Linux retains `/workspace` default/validation, guest-directory check and local BatchMode probe, which currently occur outside alias-writing helpers (`src/editor.rs:32`, `:61`, `:88`, `:409`). Choose macOS omitted `path` as discovered `guest.account.home`; validate any supplied absolute path as a directory reachable by the working account, using positional arguments and the same bounded handoff check. This is an implementation choice requiring reconciliation/qualification in 50's currently unresolved macOS path contract. It does not select the separate Files-page workspace/Git roots in C-7, and never asserts a macOS `/workspace`. Remote aliases consume P2's stable `--remote-guest deviceId computerId` executable path; local Linux uses packaged `msb ssh serve --stdio --no-start --no-inactivity-timeout` (`src/editor.rs:807`; `src/remote.rs:1802`). For local macOS alias transport choose NEW `silod --guest-ssh computerId`; it uses same-euid local handshake and canonical `guest.ssh` raw upgrade, then forwards stdin/stdout. Owner `guest.ssh` revalidates running ID/generation, resolves the current NAT lease with `guest_access::guest_address`, and opens TCP to that guest port 22. This must forward the guest SSH protocol bytes, not wrap them inside an already authenticated SSH command. Guest SSH authenticates with the owner's per-computer setup key locally; read the existing account key and pinned known-host record, never generate another account or expose a password. Existing setup already installs its public key (`src/macos_computers/guest_access.rs:77`, `:260`, `:324`; `src/macos_computers/personalize.rs:54`; `src/macos_computers/offline_setup.rs:700`). Pin the guest host key in the alias; do not inherit the internal runner's `accept-new` after preparation.

For remote macOS `guest.prepare`, choose validated Ed25519 controller public-key installation into the working account's authorized_keys through the authenticated owner setup key, preserving existing keys and atomically/private updating the file. This is NEW adapter work: the personalization script replaces authorized_keys and cannot be reused as a remote append command. Return user and pinned host key, then let the controller's per-device private key authenticate through canonical owner `guest.ssh`; private keys never travel. Probe exact key ownership, duplicate installation, host-key changes, forwarding restrictions and lease/generation races before enabling this relay. A stale lease mapping to another VM is a narrow unresolved risk: resolve/revalidate computer generation and rely on pinned guest host key before credentials; qualify isolation under rapid restart/deletion. The TCP/helper/key design is compatible with existing leases/SSH/setup seams but not already implemented or evidenced as a canonical stream adapter (C-7/B-11/B-14).

Alias remove deletes only its owned config, and removes the exact generated Include only when its shared root has no entry; it does not revoke guest login keys or other alias configs ([50 alias methods](../50-access-network-files.md#guestsshaliasensure)).

### 2.5 Step order and deterministic tests

1. **Confirm merged seams and run disposable mechanism experiments.** Freeze P1 bytes, P2 RequestContext/owner selector and job/event hooks. Prototype both platforms' stdin, raw bytes, root execution, guest process-group exit confirmation, native no-replace/CAS and watch helper availability with one-command disposable harnesses. Port only qualified decisions. These experiments are future implementation work; none ran for this design.
2. **Account and bounded exec tracer.** Write a failing behavior test at the process/target seam, then the minimal real adapter. Cases: immutable ID after name change, stopped guest never starts, guest uid/home, account/root, argv metacharacters as data, stdin EOF, invalid UTF-8 bytes, exact-cap success/cap+1 error, nonzero status/signal and guest timeout cleanup. Test the runtime secret/input distinction independently of the new API builder.
3. **File tracer.** Binary/ranged reads, open-inode metadata, atomic/private overwrite, parent modes, two-client create-only winner, null-hash create-only, stale hash, concurrent non-engine edits, symlinks, missing/directory unlink, permission failure and stop during operation. An independent reader must never observe partial bytes or a permissive temporary mode. Boundary tests assert real filesystem behavior rather than merely restating generated commands.
4. **Exec jobs.** Commit acceptance before launch/return; preserve job after requester disconnect/Keep running; ordered stdin/close, bounded interleaved replay, deduplicated start, guest process-tree cancellation and concurrent cancel/natural exit. Crash after terminal commit/before publication, restart/get/show/ack and retention deletion. Interrupted tracking becomes visible uncertainty/`lost`; it is never replayed as a fresh run.
5. **Aliases and remote routing.** Owned/unowned config symlinks, Include false option/refusal, ensure twice, ID stability after rename, remove twice/last-entry cleanup, computer/device/channel isolation. Verify remote ensure returns controller-local paths and owner preparation targets the exact computer ID. No automatic replay of exec/input/write/remove after socket loss.
6. **Watch and delivery.** Linux inotify/macOS native watch, atomic rename, coalescing, helper loss/overflow, stop-generation changes, unsubscribe/disconnect cleanup and two-client isolation. Use P2 barriers, gaps and re-read recovery over its framed SSH session. Exec output sequences and envelope sequences must not be conflated.
7. **Live qualification and repository checks.** Run the matrix below on disposable Dev guests, record commands/versions/raw evidence, then required Rust tests/fmt and UI checks only if UI code changed ([IMPLEMENTATION brief](../IMPLEMENTATION.md#implementer-brief)). Follow [probe rules](../probes/00-probe-rules.md); never claim a design review closed a live probe.

### 2.7 Risks and release gates

- **Guest termination is new work.** SSH kill is insufficient; B-12 refutes it. Ship only after real process-tree signal/exit confirmation on both guests.
- **Serialized-limit policy needs qualification.** Preserve stdout-only `output_too_large`; privately spool uncapped stderr. Reject a complete bounded-exec result or unpaged list that exceeds 4 MiB with existing `internal` protocol-size failure, never truncation or an invented stderr cap/paging scheme. Validate replay retention at admission against P1's actual bytes/chunk/envelope expansion. B-32's 256/768 KiB and 30/180 s values are inferred candidates, not measured defaults; `timeoutMs` remains required. Run serialization fixtures, real workload measurements and spool ENOSPC/cleanup tests in B-32. If the spec requires successful oversized replies, the exact needed reconciliation is a bounded-result/list size or chunking contract; this design does not assume transport framing itself resolves it.
- **Conditional writes are not solved by SFTP support.** Native no-replace/CAS behavior, concurrent non-engine writers and symlink races need primary-source research and deterministic/live qualification. If the requested comparison semantics cannot be guaranteed, record an explicit contract amendment before advertising the method, not an undocumented best-effort CAS.
- **Credentials and helpers have distinct boundaries.** Wire account never exposes password/key. Guest helper selection cannot assume Python or working macOS developer tools; B-19 observed missing Git/LFS/Xcode tools.
- **Persistence does not promise process continuation.** Completed outcomes persist; running process and output-ring recovery remains B-37. Keep uncertainty visible and never reexecute captured argv after recovery.
- **Controller aliases are local effects.** Generic remote routing must preserve that exception, shared Include safety and ID/channel isolation.
- **Normal calls have no legacy path.** Convert necessary stored name keys only at launch through existing runtime migration; never preserve old aliases or runtime fallback.

First implementation action: build the two-platform bounded-exec tracer with raw bytes and confirmed guest process-group cancellation before exposing exec jobs.

### 3.3 Capture, retention, settings and remote behavior

**Capture.** Default to manual; automatic capture requires the owner setting to be positive, checked both before acceptance and after queue admission. Ordinary creation uses `reason:"manual"`; engine-owned before-restore captures always use policy kind manual. Return the exact committed checkpoint through `operations.job.finished.result`, after native verification or macOS final-folder commit. Preserve running memory capture refusal and resume-on-failure; do not quietly fall back to disk. Clients truncate only the task portion to keep the complete automatic label within 80 printable characters. `checkpoints.create` still initially returns `{jobId}`, not the checkpoint synchronously (`src/runtime/checkpoints.rs:586`, `:648`, `:719`, `:726`; `src/macos_computers/checkpoints.rs:342`, `:373`, `:381`; [20 §1.2.1](../20-checkpoints-exports-preparation.md#121-checkpointscreate)).

**Retention.** Mark cleanup due only after a successful verified automatic capture. Failed capture never removes an older checkpoint. Preserve the captured result even if housekeeping is blocked; publish state/diagnostics for the deferred cleanup rather than turn a good checkpoint into a failed capture. Release the capture's computer gate before requesting Linux's device-wide deletion lane, otherwise capture and cleanup deadlock. In that lane recompute candidates from current records and the current owner setting; recheck all native dependency/pending/journal blockers immediately before each delete. Use ordinary safe deletion, never `--force`. Pinned excess records stay visible with their existing `deleteBlocker`; physical native data can remain in existing cleanup journals after a safe entry-only deletion (`src/runtime/checkpoints.rs:2627`, `:2637`, `:2694`, `:2741`, `:2757`; `src/macos_computers/checkpoints.rs:719`; [20 §1.4](../20-checkpoints-exports-preparation.md#14-checkpoints-before-unattended-runs-automatic-checkpoints)).

Recover outstanding intents at launch; retry after dependency release, Start completing a pending restore, restore settlement and explicit deletion. Also service a bounded retry in P2 upkeep so no client must stay connected. Take a nonblocking gate and leave intent pending under contention. Clear intent only after required record deletions finish; keep native deferred cleanup under its existing journal. An I/O failure preserves retry state and reports the specific checkpoint. Qualify timer cost as the checkpoint portion of B-36, without changing P2's global timer policy.

**Settings.** Accept integers in `0..=u32::MAX`; reject negative, fractional, overflow or nonnumeric values atomically with the rest of the patch. Apply default 3 in engine reads and policy, not solely in TypeScript. Count 0 rejects automatic creates, suspends pending retention and removes no existing checkpoint. Changing a positive count does not itself schedule deletion; the next successful automatic replacement applies the new count. Outstanding intents use the current count, so increasing it protects additional records; off prevents each subsequently admitted deletion. A delete already admitted before the off setting commits finishes at its existing safe boundary; no later candidate is admitted. Serialize the short setting check/deletion admission boundary, never hold the settings mutex over VM or filesystem work. Emit P2 `settings.changed` and preserve existing write-protection/save-error behavior (`src/settings.rs:111`, `:148`, `:183`, `:245`; [60 §2](../60-connections-settings-services.md#2-settings-settings), lines 321–353, 402; [20 line 445](../20-checkpoints-exports-preparation.md)).

**Launch upgrade.** Version durable layouts explicitly. Existing checkpoints become policy kind manual, preserving reason, native identity, dates, memory fields and journals. No serde default that accepts the old layout indefinitely and no conversion on create/read. Malformed/unreadable metadata remains protected; conversion failure keeps ordinary changes closed until launch recovery resolves it. Missing setting means default 3 and need not write an explicit preference. Run conversion before macOS checkpoint sweep: the current sweep deletes directories with unreadable metadata, so a new policy-field validator must not misclassify an unconverted record as garbage (`src/macos_computers/checkpoints.rs:260`). Crash/restart conversion is idempotent under P2 startup ownership ([95 §3](../95-decisions.md#3-amendments-owner-2026-10-13-later); `src/runtime/checkpoints.rs:163`, `:185`, `:333`; `src/macos_computers/checkpoints.rs:26`, `:65`; [p2 §1.5](p2.md#15-main-thread-vm-queues-and-native-windows)).

**Remote methods.** Add delete/abandon/usage through the same canonical owner dispatcher as create/restore/fork; discriminate by inventory kind, not checkpoint ID format. Owner paths, policy, gates, records, results and jobs remain on the owner. Delete and abandon are jobs; usage is a query. Preserve existing Linux final values and macOS delete null result, not a made-up unified mutation response. C-5 is resolved here by the flat params above and owner platform adapter; no singular names or action-string dispatcher. Preserve existing operation budgets/start conditions where applicable ([20 §§1.2.4–1.3](../20-checkpoints-exports-preparation.md#124-checkpointsdelete), lines 332–436; `src/remote_access.rs:144`; `src/remote.rs:981`, `:1336`).

**macOS usage.** Return measured memory-file `sizeBytes`, `totalBytes:null` for the unmeasured aggregate, and omit clone disk/private/reclaimable sizes. Project pending-restore and journal blockers from the same function used by deletion. Do not sum `du`, logical clone sizes or `st_blocks` into bytes deletion would free (`src/macos_computers/checkpoints.rs:79`, `:435`, `:719`; `src/macos_computers.rs:2044`; [20 §1.2.6](../20-checkpoints-exports-preparation.md#126-checkpointsusage), lines 399–406).

### 3.4 macOS abandon: proposed C-8 resolution and proof gate

Define abandon at the same safety boundary as Linux: success is possible only while original live files still exist; it cannot undo a restore that already replaced them. A valid **staging** journal can discard staged files, sync, remove the journal and preserve the stopped original computer and all completed recovery checkpoints. A **swapping** journal must first finish existing roll-forward recovery and persist its pending restore; then return the explicit already-replaced refusal. A settled pending restore also refuses, directing Start or another Restore. An unreadable journal preserves every file and refuses. No journal/pending restore returns a no-unfinished-restore error. Never clear `pendingRestore` just to release its checkpoint pin (`src/runtime/checkpoints.rs:2412`, `:2418`, `:2444`; `src/macos_computers/checkpoints.rs:518`, `:674`, `:696`, `:705`; `src/macos_computers.rs:527`, `:2016`).

This is a **new adapter decision**, not behavior established by 95 or existing probes. C-8 remains a merge gate until failure-injected staged/swap tests prove the boundary, including the loader's automatic settlement before dispatch. Do not manufacture a staging state after startup has already settled it. Factor journal classification/settlement so explicit abandon can inspect a stopped failed restore without entering ordinary capture's setup-ready refusal, while startup recovery remains authoritative. Result is null on successful macOS abandon, following existing macOS checkpoint mutation convention; Linux retains its specified `ApplicationSource`. Cancellation is supported while waiting; running rollback/settlement is noncancellable unless a safe seam is separately proved ([20 §1.2.5 and §6 Q2](../20-checkpoints-exports-preparation.md#125-checkpointsabandonrestore)).

### 5.3 Revocation and removal

Use `RemovalIntent {device_id, saved_address, saved_record_generation, controller_public_key, phase: revoke_pending|owner_confirmed|local_cleanup_pending}`. Store only public key material. 1. Read the saved owner and this controller's Connections public key. Quiesce local creation/reconnection of routes for that owner while removal is in progress.
2. Call owner `connections.keys.revoke` as a canonical Change with durable idempotency.
